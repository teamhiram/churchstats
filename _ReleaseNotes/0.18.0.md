## 本バージョンでの追加・変更内容

### ログイン時に login_logs へ記録

- **背景**: Supabase の `login_logs` テーブルは初期スキーマで定義されていたが、ログイン成功時に挿入する処理がなく、常に空だった。
- **対応**: ログインフォーム（`LoginForm.tsx`）で `signInWithPassword` 成功後、認証済みセッションで `login_logs` に1行挿入するようにした。
- **記録内容**: `user_id`（auth.users.id）、`email`、`user_agent`（ブラウザの User-Agent）。`ip_address` は未記録（将来 API Route 等でサーバー側から付与する拡張が可能）。
- **挙動**: 挿入に失敗してもログインは成功したままリダイレクトする（try/catch で囲み、失敗時は console.error のみ）。RLS の `login_logs_insert_authenticated` により、認証済みユーザーが自分用のログを挿入できる。

### 設定をサイドバー付き画面に変更

- **ヘッダー**: 「設定」はドロップダウンではなくリンク（`/settings`）に変更。クリックで設定画面を開く。アカウント詳細はトップレベルで、人の形のアイコンとしてヘッダー一番右に配置。
- **設定画面**: 左にサイドバー、右にコンテンツのレイアウト。サイドバーには「枠組設定」「システム設定」、グローバル管理者時は「ユーザ・ロール管理」、管理者時は「デバッグ」セクション（各種数値・全テーブル・在籍期間不確定リスト・重複出席）を表示。デバッグ項目はアンバー色で区別。サイドバーを隠す／表示するボタンを設置。
- **コンテナ**: 設定画面の一番外のコンテナは左右・下の余白をなくし（main の padding を負のマージンで打ち消し）、上はヘッダー高さ分を確保して重ならないようにした。

### システム設定・ユーザ・ロール管理

- システム設定ページから「ユーザー・ロール管理」セクションを削除。同機能はサイドバーの「ユーザ・ロール管理」から遷移。
- ユーザ・ロール管理ページ（`/settings/roles`）で、一覧および詳細の名前の下にメールアドレスを表示。

### デバッグ・全テーブル

- 「在籍期間不確定リスト」をデバッグサイドバーに追加（`/debug/enrollment-uncertain`）。全テーブルページからは「在籍期間不確定リスト」「集会重複検知」へのリンクを削除。

### 集会重複の大元防止

- **原因**: 同一（日付・種別・地区／地方／小組）の集会が複数行になる要因は次のとおり。
  - **競合**: 主日出欠や集会取得で「既存を確認してから insert」しているが、同時リクエストで両方とも「ない」と判断して二重挿入する。
  - **複数経路**: 主日集会の「取得または作成」がサーバー側（`ensureSundayMeetingsBatch`）とクライアント側（`SundayAttendance` の `ensureMeetingForDistrict`）の両方にあり、どちらかが後から同じキーで insert すると重複する。
  - **DB に一意制約がなかった**: 同じ論理集会の重複行を禁止する制約がなく、上記がそのまま重複として残っていた。
- **対応**:
  - **マイグレーション 039**: 既存の重複行を1本にまとめ（出席・名簿は代表行に寄せてから重複集会行を削除）、その後「同一 (event_date, meeting_type, district_id, locality_id, group_id) は1件」となる一意インデックスを追加。これにより新規の二重挿入は DB でエラーになる。
  - **アプリ**: 主日集会の「取得または作成」で insert が unique_violation (23505) になった場合、同じ自然キーで既存行を取得してその id を返すようにした（`meetings/sunday/actions.ts` の `ensureSundayMeetingsBatch`、`SundayAttendance.tsx` の `ensureMeetingForDistrict`）。手動の「集会を新規作成」では、重複時は「この日・この地区／小組の集会は既に登録されています」と表示するようにした（`meetings/new/page.tsx`）。
