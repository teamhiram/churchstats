## 本バージョンでの追加・変更内容

### 地方選択ポップアップの不具合修正

- **現象**: 地方を切り替えるポップアップを開いたとき、地域タブ（「北海道・東北」「北関東」「南関東」など）をクリックまたはタップしてもタブが切り替わらない、あるいは反応が不安定になることがあった。
- **原因**: ポップアップのコンテンツ領域がオーバーレイ（`z-[100]`）と同じ階層で描画されており、タブがオーバーレイの背面に隠れたり、タッチデバイスで `onClick` だけでは意図どおり発火しない場合があった。
- **対応**:
  - **前面表示**: ポップアップ本体（ダイアログの白い枠）に `z-[101]` を付与し、オーバーレイより前面に描画するようにした。これによりタブが常にクリック／タップ可能な状態になる。
  - **タッチでのタブ切り替え**: 地域タブのボタンに `onPointerDown` を追加し、`onClick` に加えてポインターが下がった時点で `setLocalityPopupAreaIndex(idx)` を実行するようにした。タッチ操作でも確実にタブが切り替わる。
  - **オーバーレイで閉じる**: ポップアップのオーバーレイ（半透明の黒背景）をクリックしたときにポップアップを閉じるようにした。`onClick` で `e.target === e.currentTarget` のときのみ `setLocalityPopupOpen(false)` を呼び、ダイアログ本体のクリックでは `stopPropagation` により閉じないようにしている。

### バージョン表示

- ヘッダー右上のバージョンバッジを 0.20 に更新。

### サイトタイトルをルートへのリンクに

- **変更内容**: ヘッダー（モバイル・PC 共通）のサイトタイトル「召会生活統計」を `<Link href="/">` でラップし、クリックでルート（`/`）に遷移するようにした。
- **UI**: ホバー時に `hover:text-white/90` で少し薄くし、リンクであることが分かるようにしている。

### 派遣マトリクスのスクエア色とメモ表示の修正

- **スクエアが白くなる不具合**: 個人ページおよびダッシュボードの出欠マトリクスで、派遣列のセルに「派遣種類」（メッセージ／電話／対面）に応じた色（薄紫〜濃い紫）を付与する際、`colorClass` にオブジェクト全体を渡していたため `[object Object]` がクラス名になり背景が適用されず白く表示されていた。`dispatchColors.square` を背景クラス、`dispatchColors.border` を枠線クラスとして参照するように修正し、正しく色が表示されるようにした。
- **メモドットのコントラスト**: 派遣マトリクスでメモありを示すドットは従来どおり暗いグレー（`bg-slate-700`）だったが、対面（濃い紫 `violet-500`）のマスでは背景とのコントラストが不足して見づらかった。対面のマスに限りメモドットを白（`bg-white`）にし、薄い紫のマスでは従来どおり暗いドットのままとした。

### ヘッダー／フッターのメンバー検索

- **PC**: ヘッダー右端のアカウントボタンの左に虫眼鏡の検索ボタンを配置。クリックするとボタンが検索フィールドに変わり、左方向に伸びる。同時に左側のメニュー（ダッシュボード・週別集計・出欠登録・名簿管理・設定）は非表示になる。ヘッダー外をクリックするか Esc で元に戻る。検索候補をクリックすると該当メンバーの個人ページ（`/members/[id]`）へ遷移する。
- **スマホ**: フッターのアカウントボタンの左に検索ボタンを配置。タップで画面中央にアラート風の小さなポップアップを表示。検索入力で名前・ふりがなによりメンバーを絞り込み、候補をタップで個人ページへ遷移。ポップアップの結果リストは 5 件分の高さに固定し、6 件以上はスクロールで表示。
- **検索ロジック**: 現在選択中の地方のメンバーを `/api/members?locality=...` で取得し、クライアントで名前・ふりがなをフィルタ。ふりがなは DB 上カタカナで保存されているため、検索時にカタカナをひらがなに正規化して比較し、ユーザーがひらがな・カタカナのどちらで入力してもヒットするようにした。
- **レイアウト**: PC ではアカウントボタン位置を動かさないため、ヘッダーを `grid-cols-[auto_1fr_auto]` の 3 列にし、右端列にアカウントを固定して検索フィールドは中央列のみで伸縮する形にしている。

### 出欠登録：3 ボタン（ー／○／×）とグルーピング・セクションヘッダー

- **出欠入力**: 従来のトグルを廃止し、**ー（未記録）／○（出席）／×（欠席）** の 3 ボタンに変更。未記録のまま保存しても欠席として自動記録せず、名簿にいるメンバーで記録のない者は「記録なし」セクションに表示される。
- **グルーピング**: 1 層目は「出欠別」（出席・欠席・記録なしの順）。2 層目は「リスト別」（レギュラー・準レギュラー・プール）。**表示モード**では 2 層目はなし（出欠別のみ）。**記録モード**では 2 層目を「リスト別」にし、プールは初期状態で閉じている。
- **セクションヘッダー**: サイトヘッダーに合わせてニュートラルグレー（青みのない `gray`）の背景・白文字を適用。1 層目は `bg-gray-800`（濃い）、2 層目は `bg-gray-500`（薄い）で階層を区別。ホバー時はそれぞれ 1 段階明るく（`gray-700` / `gray-400`）。
- **対象画面**: 主日集会・祈りの集会・小組集会の 3 つの出欠登録画面で同一仕様。

### 出欠登録（主日）：「全ての地区」選択の反映と読み込み完了

- **現象**: 主日集会の出欠登録で地区フィルターから「全ての地区」を選んでも、URL は `district_id=__all__` のままなのに表示は特定の地区（例：稲城）の名簿のままだった。また「全ての地区」を選ぶと「読み込み中…」のまま進まず、名簿が表示されないことがあった。
- **原因**:
  - サーバー側で `effectiveDistrictIdForCurrentLocality` に `allowAllDistricts: true` を渡していなかったため、URL の `__all__` が採用されず現在地方のデフォルト地区 ID にフォールバックしていた。
  - フィルターバー（クライアント）で `district_id` が `__all__` のときを「有効な値」として扱っておらず、ドロップダウンの表示がデフォルト地区になっていた。
  - 「全ての地区」用の非同期データ取得に `.catch()` がなく、エラー時に `setLoading(false)` が呼ばれず「読み込み中」で止まることがあった。
- **対応**:
  - 主日集会ページ（`page.tsx`）で `effectiveDistrictIdForCurrentLocality(params.district_id, layoutData, { allowAllDistricts: true })` を渡すようにし、URL の `district_id=__all__` をそのまま採用するようにした。
  - 出欠登録のフィルターバー（`MeetingsFilterBar.tsx`）で、`district_id` が `"__all__"` のときも有効な選択として扱い、ドロップダウンに「全ての地区」が正しく表示されるようにした。
  - `SundayAttendance.tsx` の「全ての地区」用・合同集会用の非同期処理に `.catch()` を追加し、エラー時も `setLoading(false)` で読み込み状態を解除するようにした。コンソールに `SundayAttendance all-districts load:` / `combined load:` のログを出力し、原因調査しやすくした。

### 出欠登録（主日）：出欠別表示での「出欠(#)」をセクション別人数に

- **現象**: 主日集会の出欠登録でグループを「出欠別」にしたとき、**欠席**セクションの列タイトル「出欠(#)」の#が常に 0 で表示されていた。同様に**記録なし**セクションでも 0 だった（いずれも「出席者数」で集計していたため）。
- **対応**: 出欠別（group1 === "attendance"）のとき、セクション種別に応じて「出欠(#)」の数値を切り替えるようにした。
  - **出席**セクション → 出席人数（従来どおり）
  - **欠席**セクション → 欠席人数（`attended === false` の人数）
  - **記録なし**セクション → 記録なし人数
- **対象**: グループ1のセクションヘッダーと、グループ2がある場合のサブセクションヘッダーの両方。地区順・小組順など他グループのときは従来どおり出席人数を表示。
