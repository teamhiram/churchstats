# ChurchStats v0.5

2026/02/05
local test only.

0.4 に引き続き開発。サイト高速化プラン（最新版）に沿って、体感速度の向上・ユーザー情報取得の短縮・週別集計の軽量化・データベース側のチューニングを実施した。加えて、キャッシュ（TanStack Query・localStorage 永続化）・コンフリクト検知（楽観ロック）・枠組設定の一括取得による高速化を追加した。

## 本バージョンでの追加・変更内容

### 体感速度の向上（loading 表示の追加）

- **メンバー一覧:** `/members` に `loading.tsx` を追加。データ取得中はレイアウト＋スケルトン（見出し・フィルター・テーブル領域の枠）を表示。
- **メンバー詳細:** `/members/[id]` に `loading.tsx` を追加。
- **集会詳細:** `/meetings/[id]` に `loading.tsx` を追加。
- **集会トップ:** `/meetings` に `loading.tsx` を追加。
- **システム設定:** `/settings` に `loading.tsx` を追加。
- 既存のダッシュボード・週別集計一覧の loading とあわせ、主要ページで「何も出ない時間」を減らし、すぐに反応しているように見せるようにした。

### ユーザー情報取得の短縮（レイアウトの初動）

- **`getCurrentUserWithProfile` の見直し:** 従来は「プロフィール → 地区 → 地方」の 4 回の DB 問い合わせを直列で実行していた。Supabase の埋め込みリソース（結合）を使い、**1 回のクエリ**で profile・district・locality を取得するように変更。
- **効果:** 毎回の画面表示で最初に走る「誰でログインしているか」の処理が短くなり、どのページを開いても初動が速く感じられる。

### 週別集計の軽量化

- **出席・小組出席の取得方法:** `attendance_records` と `group_meeting_attendance` の取得で、集会 ID や記録 ID のリストが長い場合に `.in()` が失敗したり負荷が高くなったりしないよう、**200 件ずつチャンク**に分けて問い合わせするように変更。
- **並列実行:** 各チャンクの取得を `Promise.all` で並列に実行するようにし、全体の待ち時間を短縮。

### データベース側のチューニング

- **マイグレーション 011:** `supabase/migrations/011_performance_indexes.sql` を追加。
  - `districts(locality_id)` にインデックスを追加（地方で地区を絞るクエリ用）。
  - `groups(district_id)` にインデックスを追加（地区で小組を絞るクエリ用）。
- **チューニング手順のドキュメント:** `_RealeaseNotes/PerformanceTuning_DB.md` を追加。Query Performance Advisor の使い方・インデックスの確認・接続プール（Supavisor）の確認・リージョンの考慮を、ノンエンジニア向けのチェックリストとして記載。

### キャッシュ・ローカル優先（体感のさらなる短縮）

- **TanStack Query の導入:** 名簿（`/members`）と週別集計（`/meetings/list`）のデータをクライアントでキャッシュするようにした。
- **初回表示:** サーバーで取得したデータを `initialData` として渡すため、初回から待たずに表示。
- **再訪時:** 同じページへ戻ったときはキャッシュを即時表示（5 分間はキャッシュをそのまま使用）。
- **localStorage 永続化:** 一度見たデータはブラウザをリロードしたり再訪したりしても、まずキャッシュから即表示。キー `churchstats_rq_cache`、保持 7 日。
- **裏でのバージョン確認:** 30 秒ごとに `/api/data-version` で DB の変更有無を確認。変更があれば該当クエリを無効化し、次回表示時に再取得する。
- **週別集計:** `/api/meetings-list` を追加。週別集計ページはサーバーから initialData を受けつつ、以降はキャッシュで即表示。

### コンフリクト検知（楽観ロック）

- **メンバー編集:** 編集中に取得した `updated_at` をサーバーに送り、`WHERE id = ? AND updated_at = ?` で更新する楽観ロックを導入。
- **他ユーザーが先に更新した場合:** 「他のユーザーが先にこのメンバーを更新したため、保存できません。画面を更新して最新の内容を確認してから、再度保存してください。」という理由を枠付きで表示する。
- **地区・小組の更新:** 設定画面での地区名・小組名の変更時に `updated_at` を更新し、キャッシュ無効化の判定に利用。

### 枠組設定の高速化

- **「各リスト読み込み中…」の短縮:** 地区・小組の「＋」は**初期はすべて閉じた状態**に変更。ページを開いた直後はリスト取得を行わず、表示が速い。
- **一括取得 API:** `/api/organization-lists` を追加。所属地方内の全地区・全小組の「レギュラー/非レギュラー名一覧」を**1 リクエスト**で取得。
- **バックグラウンドでキャッシュ:** 枠組設定を開いたときに上記 API を 1 回だけ呼び、結果をキャッシュに流し込む。ユーザーが「＋」で開いたときは、キャッシュがあれば即表示される。

### データベース側のチューニング（続き）

- **マイグレーション 013:** `supabase/migrations/013_districts_groups_updated_at.sql` を追加。
  - `districts` と `groups` に `updated_at` 列を追加（キャッシュ無効化・コンフリクト検知用）。既存行には `DEFAULT now()` が入る。

## データベース

- **新規マイグレーション:** `011_performance_indexes.sql` を適用すること。本番環境では `supabase db push` または既存のデプロイ手順に従って実行する。
- **013_districts_groups_updated_at.sql:** キャッシュ・コンフリクト機能を利用する場合は適用すること。Supabase ダッシュボードの SQL Editor で以下を実行してもよい。
  ```sql
  ALTER TABLE public.districts ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ DEFAULT now();
  ALTER TABLE public.groups ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ DEFAULT now();
  ```
- 既存の 001〜010 が適用されていれば、011 および 013 を追加適用すればよい。
