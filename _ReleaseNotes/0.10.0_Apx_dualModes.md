# 下準備
1）下準備としての修正：「出欠の読み込み時に、NULL を true に変換する処理」を削除。出欠にfalse,trueの2種類が存在することを想定する。

2）出欠登録画面を編集モードと閲覧モードを分けます。
デフォルトは閲覧モードになります。

# 閲覧モード
・閲覧モードはattendance_recordsをfetchして表示する。レギュラーモードは関係ない。
・何も登録されていない場合に下記のメッセージを表示：
　まだ記録はありません。
・登録がある場合、一覧テーブルで表示。
・表示設定は閲覧モードでも作動するように。ただし、フリー検索を無効化する
・タブ直下に固定行（fixed）を設け、ボタン[記録モードに切り替える]を設置→記録モードに遷移する。固定行についての補足：PCの場合グロナビはすでに固定化しているので、その下にstickする形になる。スマホの場合はグロナビはフッターにあるので影響はない。

# 登録モード

・登録に保存というステップを挟む：「記録モードに切り変える」をクリックすると、[キャンセル] [保存する] の二つのボタンに変わる。登録モードではデータベースへの即時的反映ではなく、[保存する]をクリックした後に初めてattendance_recordsに反映する。

・登録モードの叩き台：登録モードは現行の画面を元に以下のように改修する。

・欠席の明示的記録：まだ教会に来たことがないときに記録がないと「欠席」になるのはおかしいので、そもそもattendance_recordsに記録を残さない。attendance_recordsに残すのは出席・欠席の2種類のみである。

・出欠記録からの除外・削除処理1（在籍期間での判断）：レギュラーリストをもとに表示させているので、遡って登録する際、当時その地区/小組に所属していなかったメンバーの名前が出てくることが想定されます。名簿に「ローカルメンバー転入日」と「ローカルメンバー転出日」の欄を設けてください。SQL文もください。ローカルメンバー転入期間外の場合、レギュラーリスト（枠組設定で設定されて、毎週の記録のためにあるので、期間の概念がない）にあってもデフォルトでは表示しない。フリー検索でヒットしてクリックした場合、赤文字として表示します。クリックすると、ポップアップで「このメンバーは在籍期間外です。名簿編集にて「ローカルメンバー転入日」や「ローカルメンバー転出日」をご確認ください。」と警告し、追加を阻止する。

・出欠記録からの除外・削除処理2：名前の左側に赤丸の「ー」記号を設ける。クリックするとその名前は出欠編集画面から消えます。つまり、保存する際にattendance_recordsに書き込まれない名前になる。同じ集会において、すでに書き込まれている場合は削除処理を走らせる。言い換えると、 その編集セッション中だけ表示から消す（保存時に DB に書き込まない／既存レコードがあれば削除）。ただし、レギュラーリストに登録されている名前の場合はポップアップアラートを出す：

過去の記録に影響はありません。今週以降に影響します。地区のレギュラーリストから外れると、今後その地区の主日の登録モードで「レギュラーリストで補完する」を押したときに、その名前一覧に含まれなくなります。

・[レギューラーリストで補完する]ボタンを設ける。記録にない名前は一時グループ[追加待ち]グループとして一番上に追加される。出欠トグルのデフォルトは欠席だが、このままではDBに追加されない。行の右端に[追加する]ボタンを設け、クリックされると一時グループから外れて通常のグループ（グルーピング設定に従う）に加わる。「記録にない名前」についての補足→実際の対象は：
* 主日・祈祷会：選択地区の district_regular_list のうち、まだ記録にない人
* 小組：選択小組の group_regular_list のうち、まだ記録にない人

・保存漏れ防止策2：ブラウザの履歴・戻るで戻ったときに、編集内容を復元する。

・合同集会の処理：出欠登録の主日集会タブの主日の日付の右に「合同集会」トグルを設置、デフォルトはOFF。ONのとき、集会は地区ごとではなく、[地方名]+[合同集会] というフォーマットで1集会として登録する。いずれの地区でONにしても地方全体に効力を及ぼします。保存時、既存レコードが地区別に複数集会がある場合、それを統合して合同集会のあるべきデータに修正する。


・主日・祈り・小組の共通化：計画では主日・祈祷会・小組を前提にしていますが、実装は3ページに分散しています。共通コンポーネント／フックにまとめる。 集会用の設定（オンライン・他地方の有無など）だけ差分にする方法を考えてください。

・保存失敗時の処理を適切に考えてください。
