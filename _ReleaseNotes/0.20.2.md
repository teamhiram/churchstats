## 事象
個人ページを本番環境では`500 Internal Server Error`になってします。
ローカルの `npm run dev` や `npm run build`では問題ない

## 原因

個人ページで「在籍メモ」を安全に表示するために使っていたライブラリ（isomorphic-dompurify）が、**本番サーバー側**で別のライブラリ（jsdom）を読み込んでいました。  
その jsdom が、さらに別のパッケージ（@exodus/bytes）を「古い読み込み方」で呼び出しており、**本番の Node 環境ではその読み込み方が許可されていない**ため、ページを表示する前にサーバー側でエラーが起き、500 が返っていました。

- ローカル開発環境ではその制約が違うため、同じコードでもエラーにならず動いていました。
- エラーは「個人ページを開いた瞬間、サーバーがページを作る前に」起きていたため、画面上には「500 Internal Server Error」しか出ませんでした。

## 解決方法

「在籍メモ」の表示方法を変えました。

- **サーバー側（本番・ローカル共通）**: 危険なタグを除いた「安全なテキスト」だけを最初に表示するようにし、問題のライブラリをサーバーでは一切読み込まないようにしました。
- **ブラウザ側**: ページが表示されたあと、ブラウザだけで DOMPurify を使ってメモをサニタイズし、リンクなどをクリックできる形に差し替えるようにしました。

この結果、サーバーでは問題のライブラリを使わずにページを返せるようになり、本番環境でも個人ページが正常に表示されます。在籍メモの「URL がリンクになる」などの表示も、表示直後にブラウザ側で反映されます。
