## 本バージョンでの追加・変更内容

### 週の数え方をアメリカ式に変更

週の定義を**アメリカ式**に統一した。

- **第1週**: 1月1日を含む週を第1週とする。
- **週の区切り**: 日曜始まり（日曜〜土曜）。これまで「月曜を week_start とする」だったものを「日曜を week_start とする」に変更した。

**影響する画面・機能**

- **週別集計**（`/meetings/list`）: 週の一覧・週番号・主日・祈りの集会・小組・派遣の集計が日曜始まりで表示される。
- **主日集会・祈りの集会・小組集会・有機的派遣**の出欠登録: 週選択ドロップダウンの週範囲が日曜〜土曜になる。主日（日曜）は週の先頭日として扱われる。
- **ダッシュボード**: 「今週」の欠席アラート・派遣モニターが日曜〜土曜の週で集計される。
- **統計（週別主日出席）**: 過去12週のグラフが日曜始まりの週で集計される。

**データベース**

- マイグレーション **015_week_start_sunday_american.sql** を適用する。既存の `week_start`（月曜日）を日曜日に変換するため、次の3テーブルで `week_start` を 1 日戻す `UPDATE` が実行される。
  - `group_meeting_records`
  - `prayer_meeting_records`
  - `organic_dispatch_records`
- Supabase の SQL Editor で手動実行する場合は、マイグレーション内の SQL をそのまま実行すればよい。`WHERE` なしの全行更新であることがツールで警告されるが、意図した動作のため問題ない。

### 週別集計テーブルの修正

週別集計（`/meetings/list`）のテーブルとアコーディオンを変更した。

- **列の追加**: 「主日人数」の右に **「祈りの集会」** 列を追加した。祈りの集会の出席者数が週ごとに表示される。
- **アコーディオン内容**: 週を展開したときの詳細を、次の **4 セクション** に変更した。いずれも **出席者のみ** を表示し、名前は改行ではなく **「、」で区切る**。
  - 主日集会
  - 祈りの集会
  - 小組出席者
  - 派遣先
- **表示順**: 各セクションの名前は **フリガナ順** でソートして表示する。

### 週別集計の主日人数をユニーク人数に変更

週別集計の「主日人数」の集計方法を変更した。

- **変更前**: その週の主日出席 **レコードの延べ数** を表示。同一週に複数の主日 meeting がある場合、同一人物が複数回カウントされることがあった。
- **変更後**: その週の主日に出席した **メンバーのユニーク人数** を表示。同一人物は 1 回だけカウントされる。

### デバッグ：主日出席のローカル／非ローカル確認

主日の出席者をローカル／非ローカル別・フリガナ順で確認するデバッグ用の仕組みを追加した。

- **ページ**: `/meetings/list/debug-jan4`
  - パラメータなし: 当年の 1/4 を含む週の主日出席者をローカル・非ローカル別に表示する。
  - **`?year=yyyy`**: 1/4 を含む週の対象年を指定する（省略時は当年）。
  - **`?date=yyyy-MM-dd`**: 指定した日曜日の主日出席者を表示する。週別集計で「ローカルのみ」オフ時に人数差が出る週の日曜日を指定すると、非ローカルが誰か確認できる。
- サーバーアクション `getDebugSundayAttendees(dateStr)` で任意の日曜日の主日出席者を取得できる。

### 主日出席の重複登録の検出・削除

同一週に同一人物が複数の主日で出席登録されているレコード（重複）を検出し、不要なレコードを削除する機能を追加した。

- **ページ**: `/meetings/list/duplicates`
  - 同じ週に 2 件以上の主日出席があるメンバーを一覧表示する。
  - 各レコードに「集会日」と「このレコードを削除」ボタンを表示。削除すると該当する `attendance_records` の 1 件が削除される。
  - **`?year=yyyy`**: 対象年を指定できる（省略時は当年）。
  - **`?week=yyyy-MM-dd`**: 特定の週だけ表示する場合、その週の日曜日を指定する。
- サーバーアクション: `getDuplicateMainAttendance(year, weekStart?)`（重複一覧取得）、`deleteAttendanceRecord(attendanceId)`（1 件削除）。

### グローバルナビの変更

グローバルナビの構成を見直した。

- **アカウントの削除**: トップレベルの「アカウント詳細」リンクを削除した。アカウント詳細ページへは、右端の **「アカウント」** ドロップダウン内からアクセスする。
- **デバッグメニューの追加**: PC・モバイルのグローバルナビに **「デバッグ」** メニューを追加した。
  - **PC**: ナビバーに「デバッグ」を追加。クリックでドロップダウンが開き、子メニューから **「全テーブル」**（`/debug/tables`）・**「重複出席」**（`/meetings/list/duplicates`）に遷移できる。
  - **モバイル**: フッターに「デバッグ」を追加。タップで上方向にポップオーバーが開き、「全テーブル」「重複出席」へのリンクを表示する。

### ビルドエラー修正（v0.9 リリース時）

Vercel でのビルドが複数回失敗した。原因と対応を記録する。いずれも **型定義の不整合** が原因で、SQL や DB まわりではなかった。

| 原因 | 内容 | 対応 |
|------|------|------|
| **1. prayerCount の型不足** | 週別集計テーブルに「祈り」列を追加したが、`WeekRow` 型に `prayerCount` が定義されていなかった。 | `MeetingsListPageClient.tsx` の `WeekRow` 型に `prayerCount: number` を追加。 |
| **2. WeekRow 型の二重定義** | `actions.ts`（`"use server"`）と `MeetingsListPageClient.tsx` で `WeekRow` が別々に定義され、クライアントからサーバー型をインポートする際に型解決が失敗していた。 | `types.ts` を新規作成し、クライアント・サーバー共通の型として分離。 |
| **3. debug/tables の Supabase 型キャスト** | `SupabaseClient` を独自の `QueryChain` 型に無理やりキャストしており、型の互換性がなかった。 | `QueryChain` を廃止し、Supabase のネイティブ API を直接呼ぶように変更。 |
| **4. Recharts Tooltip の payload 型** | Recharts の `Tooltip` が渡す `payload` は各要素の `payload` プロパティがオプショナルだが、`WeeklyBarTooltip` では必須として扱っていた。 | 型アサーションを追加し、`payload` が undefined の場合の null チェックを追加。 |
