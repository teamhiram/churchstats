## 本バージョンでの追加・変更内容

### 閲覧モード・スマホ時のメモ表示

- 閲覧モードでスマホ表示のとき、テーブル内のメモ列（ヘッダー・セル）を非表示にした。メモは従来どおり、該当する名前行の直下の専用行（スマホのみ表示）でのみ表示される。
- メモ専用行から仕切り線（上ボーダー）とグレー背景を削除。メモ本文を1文字分左にインデント（`pl-4`）して表示。

### セクション別テーブルヘッダーへの集計表示

- グルーピングでセクション表示（出欠別: 出席／欠席 など）にしているとき、各セクションの列見出し行にも、そのセクション内の集計を表示するようにした。
- 表示形式はメインヘッダーと同様の「出欠(#)」「ｵﾝﾗｲﾝ(#)」「他地方(#)」。1層目セクション・2層目サブセクションの両方のヘッダーに反映。

### テーブルの揃えの統一

- 「出欠」「ｵﾝﾗｲﾝ」「他地方」のヘッダーとデータセルをすべて左揃えに統一。従来、ｵﾝﾗｲﾝ・他地方のヘッダーが中央揃えで、セルとのずれが生じていた部分を解消。

### 名前列の幅と省略表示

- 名前列の最大幅を 9rem に制限。長い名前は省略記号（…）で切れ、出欠・オンライン・他地方・メモ列にスペースを回すようにした。

### スマホ時の列幅バランス

- スマホ表示で、出欠列を狭く（`w-14`）、ｵﾝﾗｲﾝ列をやや広く（`w-16`）、他地方列を広め（`w-[4.5rem]`）に変更。出欠とｵﾝﾗｲﾝの間の余白を減らし、他地方列に「他地方(0)」が1行で収まる幅を確保。
- 「出欠」「ｵﾝﾗｲﾝ」「他地方」のヘッダーをなるべく折り返さないように、3列すべてに `whitespace-nowrap` を指定。出欠列には `min-w-[3.75rem]` を追加し、「出欠(17)」などが1行で収まる最小幅を確保した。

### 閲覧モードでの名前リンク

- 出欠登録の閲覧モード（主日集会・祈りの集会・小組集会）で、名前をメンバー個別ページ（`/members/[id]`）へのリンクにした。記録モードでは従来どおりリンクにしない。

### メンバー個別ページの変更

- 編集ボタンを詳細コンテナ（白いカード）内の右上に移動し、名前・フリガナの右側に配置した。
- **名前のドロップダウン化**: 表示中のメンバー名をドロップダウン（`<select>`）で表示するように変更。ドロップダウンで別のメンバーを選ぶとそのメンバーの個別ページ（`/members/[id]`）に切り替わる。ドロップダウンは独立した白枠のコンテナに配置し、ページ最上部（名簿管理リンクより上）に置いた。詳細カードからは見出しの名前（h1）を削除し、フリガナと編集ボタンのみ残している。
- **名前検索ボタン（虫眼鏡）**: ドロップダウンの右隣に虫眼鏡アイコンボタンを追加。クリックで検索用モーダルが開く。モーダル内で名前の一部を入力すると Supabase で名前検索（`ilike`、最大20件）し、結果一覧からメンバーを選択できる。選択するとそのメンバーの個別ページへ遷移しモーダルを閉じる。オーバーレイクリック・Escape・「キャンセル」でモーダルを閉じる。現在表示中のメンバーは一覧で「（現在表示中）」とハイライト表示。
- **個人出欠マトリクス**を追加。ダッシュボードの出欠マトリクスを参照し、縦横を転置した形で表示する。
  - **縦（行）**: 週（W1〜W52）、縦スクロールで全週表示。週列は左寄せ。日付範囲を「(MM/dd - MM/dd)」の形式でかっこ内に表示（年省略・日月二桁）。基本的に1行表示、狭いときは折り返し。
  - **横（列）**: 祈り・主日・小組・派遣の4列。列ラベルとスクエアは中央揃え。スクエアはセル内で上下中央揃え。
  - **メモ**: 祈り・主日・小組・派遣のいずれにもメモがある週は、スクエアに枠（ring）と右下の点で「メモあり」を表示。ホバーでツールチップにメモ本文を表示。ツールチップは最小幅を確保し横書きで表示。欠席のレコードでもメモがあれば収集・表示するようにした。
  - 主日の週の算出で、`event_date` が ISO 形式（`yyyy-MM-ddTHH:mm:ssZ`）の場合に備え、日付部分のみ（`slice(0,10)`）を使って週を求めるように修正。

### デバッグ「全テーブル」の列表示切替

- 列ごとのフィルターセクションで、各列ラベルの左にチェックボックスを追加した。デフォルトはすべて ON（表示）。チェックを OFF にすると、テーブル上のその列が非表示になる。列の表示状態は `columnVisible` で保持し、テーブル切り替え時は新テーブルの列をすべて表示に初期化する。

### 週別集計の年またぎ週の主日集計修正

- 週別集計（出欠登録一覧）で、年をまたぐ週（例: 2026年1週目は日曜が 2025/12/28）を表示したとき、テーブル上の主日集計が 0 になる不具合を修正した。
- **原因**: 主日集会（`lordsday_meeting_records`）の取得に「年の範囲」（`year-01-01` 〜 `year-12-31`）を使っており、2025/12/28 の集会が 2026 年選択時に含まれていなかった。
- **対応**: 集会の取得範囲を、その年の週一覧に合わせて `weekStartRangeMin` 〜 `weekStartRangeMax` に変更。これにより 2026 年選択時も 2025-12-28（1週目の日曜）から最後の週の日曜までが対象となり、1週目の主日集計が正しく表示される。

### 有機的派遣・訪問者の表示と保存

- **派遣履歴に訪問者を表示**: 有機的派遣画面の「派遣履歴」およびメンバー個別ページの「派遣記録」で、各派遣に「訪問者: 名前1、名前2、…」を表示するようにした。訪問者が名簿にいない場合も、別途メンバー名を取得して表示する。
- **訪問者が DB に保存されない不具合の修正**: 編集ポップアップで訪問者を選択して「保存」を押しても、`visitor_ids` が DB に保存されていなかった問題を修正した。
  - **原因**: `setLocalVisitors(visitors)` の直後に `syncOne()` を呼んでいたが、React の setState は非同期のため、`syncOne` 実行時点ではまだ古い `localVisitors`（空）が参照され、常に `visitor_ids: []` が送られていた。
  - **対応**: `syncOne` に `overrides.visitors` を追加し、ポップアップ保存時は `syncOne(memberId, { visitors })` でポップアップの訪問者リストを直接渡すように変更。送信時の `visitor_ids` を文字列配列に正規化する処理も追加。

### 出欠登録・有機的派遣（UI変更）

- **ネームリストの2列化とポップアップ記録**: 有機的派遣の名簿テーブルを「名前」「記録する」の2列に変更。「記録する」または既存記録の「編集」をクリックするとポップアップが開き、派遣種類・訪問者・派遣日・メモを入力。保存・削除・キャンセルが可能。
- **派遣履歴セクション**: 表示設定の下に「派遣履歴」を追加。表示週（例: 2026/2/8〜2/14）を表示し、その週の派遣記録を一覧表示。表示順は「日付（バッジ）→ 名前 → 小組 → 派遣種類」。W# のセクションタイトルは廃止（もともと週ごと表示のため不要）。
- **編集アイコン**: 派遣履歴の各行で日付の左に鉛筆アイコンを配置。クリックで同じ編集ポップアップを開く。ボタンは padding 0・16×16px（`h-4 w-4`）で日付バッジよりコンパクトにし、グレーの角丸背景が目立ちすぎないようにした。
- **小組の初期値**: 地区に小組が1つでもある場合、初回から小組を「すべての小組」に設定し、名簿・派遣履歴を最初から表示するようにした。
- **取得エラー表示**: 派遣履歴の取得に失敗した場合、画面に「派遣履歴の取得に失敗しました: ...」と表示。原因の一つとして、`organic_dispatch_records` に `visitor_ids` カラムがない（マイグレーション 025 未実行）場合がある。その場合は `supabase/migrations/025_organic_dispatch_visitor_ids.sql` を実行すること。

### 主日まわりテーブル名のリネーム（案 B）

- **方針**: `docs/table-naming-proposal.md` の案 B（§5）に従い、主日関連の3テーブルをリネームした。小組・祈り・地区リスト系は変更なし。
- **対応表**:
  - `meetings` → `lordsday_meeting_records`
  - `attendance_records` → `lordsday_meeting_attendance`
  - `regular_member_list_items` → `lordsday_regular_list`
- **マイグレーション**: `supabase/migrations/026_lordsday_table_renames.sql` で `ALTER TABLE ... RENAME TO ...` を実行。RLS・FK・インデックスはテーブルに紐づくためリネーム後も有効。
- **アプリ**: 上記の新テーブル名を参照するように全箇所を更新（ダッシュボード・集会一覧・主日出欠・メンバー個別・デバッグ・バックアップ等）。型定義（`database.ts`）にはテーブル名のコメントを追加。デバッグ「全テーブル」の定数（`DEBUG_TABLE_NAMES`）を新名に更新。
- **バックアップ**: エクスポートは新キーで出力。インポートは旧キー・新キーの両方を受け付け、いずれも新テーブルへ upsert するため、旧形式のバックアップ JSON もそのままリストア可能。
