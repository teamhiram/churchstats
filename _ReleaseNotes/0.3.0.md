## 本バージョンでの追加・変更内容

### 有機的派遣の保存不具合対応

- **現象:** 有機的派遣画面で派遣種類・派遣日・メモを入力しても記録されない（または「Could not find the table 'public.organic_dispatch_records' in the schema cache」と表示される）。
- **原因:**
  1. **権限（RLS）:** `organic_dispatch_records` の INSERT/UPDATE はロールが admin / co_admin / reporter のときのみ許可。viewer やロール未設定のユーザーは DB 側で拒否される。
  2. **エラー未表示:** フォーム側で Supabase の insert/update の `error` を参照しておらず、失敗しても画面上に何も出ていなかった。
  3. **テーブル未作成・スキーマキャッシュ:** マイグレーション 002 が未適用の環境、またはスキーマキャッシュにテーブルが載っていない場合に「Could not find the table 'public.organic_dispatch_records' in the schema cache」が発生。
- **対応内容:**
  - **有機的派遣フォーム（`OrganicDispatchForm.tsx`）:** insert/update のレスポンスで `error` をチェックし、失敗時に画面上部に赤いバナーでメッセージを表示するように変更。権限不足（RLS）の場合は「保存する権限がありません。報告者以上のロールが必要です。」、それ以外は「保存に失敗しました: （エラー内容）」を表示。
  - **テーブル作成スクリプト:** マイグレーション 002 が未適用の環境向けに、`supabase/scripts/ensure_organic_dispatch_table.sql` を追加。Supabase Dashboard の SQL Editor で実行すると `organic_dispatch_records` テーブル・インデックス・RLS ポリシーを idempotent に作成できる。
- **運用上の注意:**
  - 有機的派遣を保存できるのは **報告者（reporter）以上** のロールを持つユーザーのみ。viewer の場合は設定 → ユーザー管理でロールを変更する必要がある。
  - 「テーブルがスキーマキャッシュにない」エラーが出た場合は、上記 SQL を実行したうえで、Supabase Dashboard の Settings → API などで「Reload schema cache」を実行するか、しばらく待ってから再試行する。

### 小組集会を専用テーブルに記録

- **変更内容:** 小組集会の記録を `meetings` + `attendance_records` から、専用テーブル `group_meeting_records` と `group_meeting_attendance` に移行。
- **マイグレーション:** `008_group_meeting_records.sql` でテーブル・インデックス・RLS を追加。`009_group_meeting_event_date.sql` で実施日用カラム `event_date` を追加。
- **小組集会画面:** 年・週・地区は共通フィルターに移したため、タブ内は小組選択・実施日・名簿（出欠・メモ）のみ。実施日は選択した週の7日間のみ選べるドロップダウン。記録がなくても小組・週を選んだ時点で実施日を選べる（選択時に記録を作成）。
- **集会一覧（週一覧）:** 小組人数・小組欠席者集計は新テーブル（`group_meeting_records` / `group_meeting_attendance`）を参照。
- **バックアップ:** エクスポート／インポートに `group_meeting_records` と `group_meeting_attendance` を追加。
- **型定義:** `GroupMeetingRecord`、`GroupMeetingAttendance` を `src/types/database.ts` に追加。

### 有機的派遣の派遣日を週内のみ選択可能に

- **変更内容:** 派遣日の入力は `<input type="date">` から、選択した週の月曜〜日曜の7日のみ選べるドロップダウンに変更。週をまたいだ日付は選べない。

### 年・週・地区フィルターの共通化（タブの上に配置）

- **変更内容:** 年・週・地区のフィルターをタブの上に1つだけ表示し、主日集会・祈りの集会・小組集会・有機的派遣の4タブで共通して使用するように変更。
- **週のフォーマット:** 小組集会と同じ「月曜始まり」の週（`getMondayWeeksInYear`）を使用。表示例: `1週目（2025/12/29 - 2026/01/04）`。
- **主日集会タブ:** タブ内の年・週・地区の3項目を削除。選択した週の日曜日を「主日：yyyy/MM/dd」形式で固定表示（例: 主日：2026/02/01）。
- **祈りの集会・小組集会・有機的派遣タブ:** タブ内の年・週・地区を削除。地区未選択時は「地区を選択してください（上記のフィルターで選択）。」を表示。小組集会・有機的派遣は小組の選択のみ残す。
- **タブ切り替え:** フィルターで設定した年・週・地区は URL クエリ（`year` / `week_start` / `district_id`）で保持し、タブを切り替えても同じ条件が維持される。
- **実装:** `MeetingsFilterBar`（共通フィルター）、`meetings/layout.tsx` で地区・プロフィール取得、`MeetingTabs` でリンクにクエリを付与。

### 出欠登録画面のUI調整

- **フィルターのラベル・幅:** 年・週・地区のラベルを削除。年のセレクト幅を狭く（約半分以下）、週のセレクト幅を広くし、グリッドを `sm:grid-cols-[minmax(0,0.4fr)_1.2fr_minmax(0,1fr)]` に変更。
- **フィルター・タブの余白:** フィルターとタブの上・左右の余白をなくし、main 内にフィットさせるため、`meetings/layout.tsx` でフィルター＋タブを `-mx-4 -mt-4 md:-mx-6 md:-mt-6` のラッパーで囲み、子コンテンツに `pt-4 md:pt-6` を付与。フィルター・タブのマージンは `m-0` に統一。
- **名簿行の高さ:** 主日集会・祈りの集会・小組集会・有機的派遣の名簿テーブルで、見出し・セルのパディングを `px-4 py-2` → `px-3 py-1.5` に、入力・セレクトの縦パディングを `py-1` → `py-0.5` に変更。出欠スイッチを `h-6 w-11` → `h-5 w-9`、ノブを `h-5 w-5` → `h-4 w-4` に縮小し、1画面に表示できる行数を増やした。
- **フック数エラー対応:** `MeetingsFilterBar` で `showFilter` が false のときに早期 return していたため、その後にあった `useMemo` / `useCallback` が呼ばれず「Rendered fewer hooks than expected」が発生していた問題を修正。すべてのフックを早期 return より前に移動した。

### 祈りの集会の追加

- **概要:** 出欠登録に「祈りの集会」タブを追加。主日集会の右隣に配置。
- **データベース:** マイグレーション `010_prayer_meeting.sql` で `prayer_meeting_records`（地区・週・実施日）と `prayer_meeting_attendance`（出欠・オンライン・他地方・メモ）を追加。主日集会と同様の出欠構造、実施日は小組集会と同様に週内で選択式。
- **画面:** `/meetings/prayer`。年・週・地区は共通フィルター。地区選択後、実施日を週内の7日からドロップダウンで選択。名簿は地区メンバーを表示し、出欠・オンライン・他地方で出席・メモを記録。主日集会と同じ5列レイアウト。

### 週の定義の変更

- **第1週の定義:** その年の「最初の日曜日を含む週」を第1週とする。例: 2026年1週目 = 2025/12/29（月）〜 2026/01/04（日）。
- **翌年にまたがる週の扱い:** その週の日曜日が翌年になる週は、その年の週一覧に含めない。例: 2025/12/29 - 2026/01/04 は 2025 年の週には含めず、2026 年の第1週としてのみカウントする。
- **実装:** `getMondayWeeksInYear`（`src/lib/weekUtils.ts`）を上記ルールに合わせて変更。`getSundayFromWeekStart` / `getSundayIsoFromWeekStart` を追加（主日表示・API 用）。

## データベース

- **002 未適用の場合:** `supabase/scripts/ensure_organic_dispatch_table.sql` を SQL Editor で実行し、`organic_dispatch_records` を作成する。
- **008 小組集会用テーブル:** `supabase/migrations/008_group_meeting_records.sql` で `group_meeting_records` と `group_meeting_attendance` を作成。
- **009 小組集会実施日:** `supabase/migrations/009_group_meeting_event_date.sql` で `group_meeting_records.event_date` を追加。
- **010 祈りの集会:** `supabase/migrations/010_prayer_meeting.sql` で `prayer_meeting_records` と `prayer_meeting_attendance` を作成。祈りの集会タブを利用する前に実行する必要がある。
- **002 適用済みでスキーマキャッシュのみの問題の場合:** Reload schema cache で解消することを想定。
